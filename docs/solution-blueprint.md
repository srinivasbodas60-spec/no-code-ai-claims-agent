# Solution blueprint

## Intake contract

Each conversation should produce a case record with:

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| case_id | text | yes | Generated by the workflow |
| request_type | choice | yes | Claim, status request, document update, or other |
| policy_number | text | conditional | Ask a clarifying question when absent |
| incident_date | date | conditional | Validate that it is not in the future |
| urgency | choice | yes | Standard, priority, or emergency |
| summary | text | yes | Short, factual summary with no invented details |
| confidence | decimal | yes | Agent confidence from 0 to 1 |
| route | choice | yes | Claims queue, service queue, fraud review, or human review |
| handoff_reason | text | conditional | Required when confidence is below threshold |

## Conversation topics

1. Start intake — greet the user, explain the scope, and collect the minimum fields.
2. Missing information — ask one focused question at a time and show what is still needed.
3. Urgency check — recognize urgent language but never promise approval or payment.
4. Status request — retrieve only the status allowed by the connected system.
5. Human handoff — create a review task when confidence is low or the request is out of scope.
6. Safe completion — summarize captured fields and provide the case reference.

## Power Automate flow

1. Trigger when Copilot Studio submits a structured intake payload.
2. Validate required fields and normalize dates, policy numbers, and urgency labels.
3. Check confidence >= 0.85; otherwise set route = human_review.
4. Write the case and immutable audit event to Dataverse or SharePoint.
5. Notify the correct Teams queue and assign an owner.
6. Return a concise confirmation to the agent.

## Data and security design

- Keep raw message content separate from the curated case record.
- Use environment variables for site URLs, queue IDs, and threshold values.
- Apply DLP policy so only approved connectors can move case information.
- Use role-based access for operations, supervisors, and reporting-only users.
- Log connector failures and route them to a support queue instead of retrying blindly.

## Production mapping

The blueprint maps cleanly to Microsoft Fabric reporting: operational records can be landed into bronze, standardized in silver, and modeled in gold for a Power BI dashboard showing intake volume, average handoff time, confidence distribution, and SLA risk.
